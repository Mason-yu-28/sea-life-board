# Sea-人生看板

一个把自己的生活当成一片海来管理的看板。**单个 HTML 文件，双击就能用，不装任何东西，不联网也能跑。**

> 它不是在管任务，是在管「一年多以后我想成为什么样的人」，然后把这句话拆成这周能做的几张卡。

**第一次用？直接看 [`docs/GUIDE.md`](docs/GUIDE.md)** —— 里面从「双击打开」写到「月底怎么复盘」，不用读别的文档。

## 它长什么样

| 视图 | 干什么 |
|---|---|
| **船舵** | 首屏。五个海域（成长 / 财务 / 健康 / 职业 / 基础）各一格，一眼看出哪一域在偏航 |
| **航行** | 日历 + 三个卡池 + 航线。岛屿卡是目标，航行卡是这周要做的事，航线是按星期自动派生的重复安排 |
| **秘宝** | 成就、影音、作品。攒下来的东西，不删只陈列 |
| **职业 / 财务 / 健康 / 成长** | 四个域各自的看板：薪资推演、收支曲线、训练热力图、投入流水 |
| **复盘** | 页内叫「潮汐」。日 / 周 / 月 / 季四档，问题不同，先给自动摘要再让你回答 |

首屏是**船舵**，七个区块，只回答一个问题：哪一域在偏航。

## 为什么是单文件

因为它要能在任何地方打开：宿舍电脑、图书馆的公用机、手机浏览器、一个 U 盘、十年后某个已经不存在的系统上。

- **零依赖**：没有 CDN、没有 npm、没有构建步骤。CSS 和 JS 全部内联。
- **一个文件 = 一份完整的产品**。发给别人只需要发一个 `.html`。
- **不联网也能用**：数据默认存在浏览器的 `localStorage` 里。

代价也很明确：这是一个 1 万行的文件，没有模块系统，改动的影响面靠纪律而不是靠编译器。`docs/audit/AUDIT-01-代码地图.md` 就是为了解决这个问题写的。

## 快速开始

```bash
# 方式一：直接打开
双击 Sea-2.8.html

# 方式二：起个本地服务（推荐，localStorage 行为更接近线上）
python -m http.server 8080
# 然后访问 http://localhost:8080/Sea-2.8.html
```

首次打开是一张**空白盘**——没有任何示例数据，你看到的第一眼就是空的，自己往里放东西。

## 数据存在哪（重要）

**默认不生成任何文件**，全部写进浏览器的 `localStorage`。想让数据同时落在一个**看得见的文件**里：**设置 → 存档文件 → 绑定**，选一个 `sea-存档.json`，之后每次改动 1.2 秒内自动写进去。

| 位置 | 说明 |
|---|---|
| `localStorage` 的 `sea_workspace_v1` | 主数据（目标、卡、流水、统计），约 10KB。**唯一真源** |
| `localStorage` 的 `sea_assets_v1` | 附件（封面、简历、凭证），base64 |
| `localStorage` 的 `sea_snap_main` / `sea_snap_assets` | 每次启动前的本机快照，出事了能捞一把 |
| IndexedDB 的 `sea_file_db` | 只存一个东西：你绑定的那个文件的句柄 |
| 你绑定的 `sea-存档.json` | **可选**，实时副本。跟「导出备份」同一个格式，可直接被导入 |
| 云端 | 可选，仅宿主支持时才有。主数据一条 + 附件按 600KB 分 4 片 |

**四条你必须知道的**：

1. **清浏览器数据 = 浏览器里那份没了。** 没有账号体系，没有服务端兜底。绑了文件的话，文件还在，重新绑定就会接回来。
2. **换设备 / 换浏览器 / 换域名，存档不跟过去。** `localStorage` 绑定 origin，`file://` 打开和 `http://localhost` 打开是两个不同的世界。存档文件可以跨过去。
3. **存档文件只是副本，不是主人。** 你在外面手改它、网盘把它回滚成旧版，都不会让你丢数据——下一次落盘会整份重写。反过来，只有当**文件比本机新**时 Sea 才会自动载入它。
4. **最省事的保险：绑一个放在网盘同步目录里的存档文件**，之后什么都不用管。没绑的话，记得「设置 → 导出备份」，那个 JSON 就是你的全部数据（含图片），导入回来即可原样恢复。

存档文件功能需要 Chromium 系浏览器（Edge / Chrome）；Firefox 和手机上没有这个 API，会自动退化成「只有 `localStorage`」，其余功能一点不减。

云端同步是可选的，需要在支持 `window.__SMART_PAGE__` 的宿主里运行（如 WorkBuddy 资料库发布态）。公开版里这个能力默认不可用，属于设计如此。

## 已知局限

- **只在 Chromium 系浏览器上验证过**（Chrome / Edge）。Safari 的 `localStorage` 配额与 iframe 策略不同，未测。
- **移动端只做了 `≤900px` 断点**，没有独立的触屏交互设计，拖拽在手机上体验一般。
- **测试覆盖不完整**：`tests/` 里有空白首启、存档与数据口径、XSS 载荷、外观回归的自动化脚本（`node tests/verify-fixes.mjs` / `verify-blank.mjs` / `probe-xss.mjs`），但拖拽、右键菜单这些交互路径仍靠人工点检。
- **单用户、单设备假设**。多人共享同一浏览器会互相覆盖。
- 部分历史 bug 的修复记录在 `CHANGELOG.md`，那是这个项目最真实的文档。

## 关于

一个人做的。从 2026 年 10 月开始，迭代了 30 多个版本，中间丢过两次数据，每次都写进了 `CHANGELOG.md`。

做它的原因很简单：市面上的待办工具都在问「你今天要做什么」，而我想找一个会问「你这个月偏航了吗」的东西。
