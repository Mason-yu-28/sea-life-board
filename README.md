# Sea-人生看板

**单文件 · 零依赖 · 数据只在你本机。** 一个用来看「这一年有没有偏航」的生活看板：一个 HTML 文件，双击就能用，不装任何东西，不联网也能跑。

`MIT` · `v2.10.0` · `无构建 / 无 CDN / 无 npm 依赖` · `纯本地存储`

> 待办工具问「你今天要做什么」。Sea 问「你这个月偏航了吗」，然后把它拆成本周能做的几张卡。

## 三条它真正在意的事

1. **一个文件就是完整的产品。** 598KB 的 `Sea-2.8.html`，CSS 和 JS 全部内联，没有 CDN、没有 `npm install`、没有构建步骤。拷进 U 盘、发到微信、扔进十年后某个陌生系统，双击都还能开。
2. **数据默认不离开你的电脑。** 不注册、不登录、没有服务端。数据写在浏览器的 `localStorage` 里；想让数据同时落成一个**看得见的文件**，在设置里绑一个本地 JSON 就行。
3. **目标和日程是两件事，所以分开放。** 岛屿卡是长期目标，航行卡是这周要做的事，航线是按星期自动派生的重复安排。月底复盘只回答一个问题：哪个海域偏了。

## 它长什么样

首屏是**船舵**：七个区块，五个海域（成长 / 财务 / 健康 / 职业 / 基础）各一格，只回答一个问题——哪一域在偏航。

![船舵](docs/assets/cockpit.png)

**航行**是核心页：上面航线池 + 周历，下面两个卡池。目标（岛屿卡）和这周要做的事（航行卡）物理上分开放。

![航行](docs/assets/sail.png)

**秘宝**只陈列不删除：成就、影音、作品三层。达成的东西从卡池流到这里，不会消失。

![秘宝](docs/assets/treasure.png)

四个域各有自己的看板，这里以**财务**为例：本周可用额度、结余率、储蓄率、消费曲线与结构。

![财务](docs/assets/finance.png)

> 截图里的数据是虚构的，由 `scripts/shots.mjs` 在临时浏览器配置里生成，不碰任何真实存档。

| 页面 | 干什么 |
|---|---|
| **船舵** | 首屏总览，看哪一域偏航 |
| **航行** | 周历 + 岛屿卡池 + 航行卡池 + 航线（重复安排） |
| **秘宝** | 成就 / 影音 / 作品，只增不删 |
| **职业 / 财务 / 健康 / 成长** | 四个域各自的看板：履历与薪资推演、收支曲线、训练热力图、投入流水 |
| **复盘** | 日 / 周 / 月 / 季四档，先给自动摘要，再让你回答 |

## 它和别的东西不一样在哪

|  | 待办类（Todoist / 滴答清单） | 笔记类（Notion / Obsidian） | **Sea** |
|---|---|---|---|
| 核心问题 | 今天做什么 | 存了什么 | 这一年偏到哪了 |
| 时间尺度 | 天 / 周 | 没有 | 年 → 月 → 周，三层都能回看 |
| 目标与任务 | 靠标签手动关联 | 自己搭表格 | 结构里就有：岛屿卡 → 航行卡 → 日历 |
| 做完之后 | 打个勾，消失 | 攒成资料堆 | 进「秘宝」，不删只陈列 |
| 数据在哪 | 云端账号 | 本地或云 | 本地，无账号 |
| 想换领域 | 换 App | 换模板 | 换一个海域，其余照跑 |

一句话：**它不是更快的待办清单，它是慢一倍但能看一年的仪表盘。**

## 适合谁

- 有一批目标要放**一年以上**，不想每季度重新开始整理
- 想同时盯住几个领域（成长 / 财务 / 健康 / 职业 / 基础），但不想开五个 App
- 能接受「先配半小时，之后每天记两分钟」的节奏
- 用 Chrome / Edge 这类 Chromium 浏览器

## 不适合谁（认真说）

- **要多人协作、共享清单的** —— 它没有账号体系，也没有并发设计
- **主要用手机记事的** —— 只做了 `≤900px` 的窄屏断点，拖拽在触屏上体验一般
- **要跨设备自动同步的** —— 这是刻意的取舍，不是没做完：没有服务端，就没有同步可依赖
- **只想记待办的** —— 用 Todoist 更省事；这套东西的价值全在「回看」，不回看就只剩负担

## 三步开始

```bash
# 1. 下载 Sea-2.8.html（Code → Download ZIP，或点开这个文件 → Download raw）

# 2. 双击打开。或者起个本地服务（推荐，localStorage 行为更接近真实环境）：
python -m http.server 8080
# 然后访问 http://localhost:8080/Sea-2.8.html

# 3. 进「航行」页 → 岛屿卡池 → ＋，建第一张岛屿卡
```

**第一次打开是一张空白盘**，没有任何示例数据——这是故意的，你看到的第一眼就该是空海。接着读 [`docs/GUIDE.md`](docs/GUIDE.md)，它从「双击打开」写到「月底怎么复盘」。

## 数据存在哪（最重要的一节）

**默认不生成任何文件**，全部写进浏览器。想让数据同时落在一个看得见的文件里：**设置 → 存档文件 → 绑定**，选一个 `sea-存档.json`，之后每次改动 1.2 秒内自动整份写入。

| 位置 | 说明 |
|---|---|
| `localStorage` · `sea_workspace_v1` | 主数据（目标、卡、流水、统计），约 10KB。**唯一真源** |
| `localStorage` · `sea_assets_v1` | 附件（封面、简历、凭证），base64 |
| `localStorage` · `sea_snap_main` / `sea_snap_assets` / `sea_snap_at` | 每次启动前的本机快照，出事了能捞一把 |
| `localStorage` · `sea_force_local` | 开关：强制只看本机、跳过云端拉取 |
| `IndexedDB` · `sea_file_db` | 只存你绑定的那个文件的**句柄**，不存数据 |
| 你绑定的 `sea-存档.json` | 可选，默认不存在。实时副本，与「导出备份」同一格式，可直接导入 |
| 云端 | 可选，只在支持 `window.__SMART_PAGE__` 的宿主里启用。公开版默认不可用 |

**两句话记住：**

1. **清浏览器数据 = 那份没了。** 没有账号、没有服务端兜底。绑过文件的话，重新绑定就接回来了。
2. **最省事的保险**：把存档文件放在网盘同步目录里，绑上，之后什么都不用管。没绑就定期「设置 → 导出备份」，那个 JSON 就是你的全部数据（含图片）。

存档文件用的是 File System Access API，只有 Chromium 系有；Firefox 和手机上会自动退化成「只有 `localStorage`」，其余功能一点不减。

## 已知局限

- **只在 Chromium 系验证过**（Chrome / Edge）。Safari 的 `localStorage` 配额与 iframe 策略不同，未测。
- **移动端只有窄屏断点**，没有独立的触屏交互设计。
- **交互路径靠人工点检**。`tests/` 里有五个自动化脚本，覆盖空白首启、数据口径、存档文件、XSS 载荷、外观像素回归；拖拽、右键菜单这些还没有自动化。
- **单用户、单设备假设**。同一个浏览器给两个人用会互相覆盖。
- **文件名还叫 `Sea-2.8.html`，实际已经是 v2.10.0**。早期就叫 2.8，后来觉得改名的收益抵不上重发一次的风险，就一直没改。真实版本看页面「设置」，或 `package.json`。

## 为什么是单文件

因为它要能在任何地方打开：宿舍电脑、图书馆公用机、手机浏览器、一个 U 盘、十年后某个已经不存在的系统上。

代价也很明确：这是一个 1 万行的文件，**没有模块系统**，改动的影响面靠纪律而不是靠编译器。所以仓库里才有 `docs/audit/` 那三份体检底稿——`AUDIT-01-代码地图.md` 就是为了回答「一万行里这一行归谁」而写的。

关于取舍的完整讨论在 [`docs/DESIGN.md`](docs/DESIGN.md)：数据模型、存储分层、派生卡为什么不能写回源，以及几个已经踩过的坑。

## 需要什么帮助

- **用起来觉得别扭的地方，直接提 issue**，说清你当时想干什么、卡在哪一步。这类反馈比功能请求有用得多。
- **布局问题请带截图和浏览器版本**，窄屏和触屏的问题需要这两样才能复现。
- 这个项目的取舍很明确（单文件、无账号、无云），**不符合这三条的改动基本不会接受**；其余的都可以谈。
