# 三个版本，保持同步

Sea 有**三个形态**。搞混的后果：线上看板读不到云端数据、公开仓库里带着作者自己的库地址，或者 02 落后 01 好几个版本还在发。

| | 01 源文件版 | 02 GitHub 发布版 | 03 资料库版 |
|---|---|---|---|
| 路径 | `Sea/01-源文件版/` | `Sea/02-GitHub发布版/` | `Sea/03-资料库版/` |
| 定位 | **唯一的源** | 派生物 | 派生物 |
| 能不能手改 | **只能改这里** | 绝不 | 绝不 |
| 由谁生成 | 人 | `git ls-files` 白名单导出 | 平台部署 → 原样下载 |
| 版本控制 | `.git`（真实历史） | 无，跟着 01 的 HEAD | 无，跟着线上 |
| 主文件名 | `Sea-2.8.html` | `Sea-2.8.html` | `Sea人生工作台.html` |
| 云端同步 | 无 | **故意没有** | **有**，`DATABASE_ID` 写死为作者的库 |
| `inject.js` | 无 | 无 | 平台注入的 `<script src="/page/page_comm/inject.js">` 必须在 |
| `data-page-node-id` | 无 | 无 | 编辑器加的锚点，868 处 |
| 首启 | 空白盘，纯本地 | 空白盘，纯本地 | 空白盘，云端有数据就拉回来 |

## 同步纪律

**同步只有一个方向：01 → 02、01 → 03。** 02 和 03 永远不会反向流入 01。任何「我在线上直接改一下」的念头都要掐掉 —— 那会让下一次派生的结果与线上不一致，而且没有任何地方记录这个差异。

改完之后，按这张表决定要重新生成哪几个：

| 你改了什么 | 01 | 02 | 03 |
|---|---|---|---|
| `Sea-2.8.html`（功能 / 样式 / 文案 / 版本号） | 改 + 提交 | **重新导出** | **打补丁上传 + 下载核对** |
| `docs/`、`README.md`、`CHANGELOG.md`、`LICENSE`、`package.json` | 改 + 提交 | **重新导出** | 不动（03 里没有文档） |
| `tests/`、`scripts/` | 改 + 提交 | **重新导出** | 不动 |
| `.private/`（历史版本、设计文档、真实数据）、`_archive/` | 改 | 不动（不在白名单里） | 不动 |

三条操作顺序，顺序错了会留下查不出来的脏状态：

1. **先 01 提交，再导 02。** 02 是 HEAD 的投影，没提交就等于导出的是工作区半成品。
2. **先 01 提交，再打 03 的补丁。** 补丁的基线是「上一个线上版本的本地副本」，不是工作区文件。
3. **03 上传完，立刻下载回来覆盖本地 `03-资料库版/`。** 不下载就等于不知道线上到底是什么 —— 2026-10-29 就踩过：平台产物列表返回的是旧静态副本，差点据它判断发布失败。

收口三问，每天改完自问一遍（有脚本，见下）：

1. 02 的文件清单和内容，是不是等于 01 的 `git ls-files`？
2. 03 的版本号（`setVerNum`）是不是等于 01 的？
3. 01 和 03 的差异，是不是**只剩**平台注入的那三处（库 ID / `inject.js` / 锚点属性）？

```bash
node scripts/sync-check.mjs          # 只读，不改任何文件
```

它八项全绿才算同步（脚本输出逐条对应）：

| 检查 | 在防什么 |
|---|---|
| 02 与 01 **逐字节一致** | 改了忘了导出，或手改了 02 |
| 01 工作区**无未提交改动** | 02 领先于版本历史，事后查不到「这版到底改了什么」 |
| 版本号一致（01 vs 03） | 线上还在跑上一版 |
| **函数集合一致**（367 个） | 01 加了新功能没打上线上（或线上残留已删代码） |
| 03 引用的元素 id **覆盖** 01 | 补丁漏插某块 DOM |
| 01 每个 `getElementById` **都有元素** | 母版自身引用了不存在的元素（最难查的「点了没反应」） |
| 03 **保留平台注入**（inject.js / 锚点 / 库 ID） | 有人整份替换了线上件，云同步静默失效 |
| 01 **未被污染**（无 inject.js、无锚点） | 把线上件当母版继续改 |

为什么用「函数集合 + 元素 id 集合」代替全文 diff：平台会把属性顺序改成 `content=... name=...`、在某些行内插 `<!--pnid:...-->`，全文比对必然一片红且全是噪声。函数名和元素 id 是**语义**，它变了才是真的漏同步。

脚本里有两个已知的正常差异，已写进白名单，不要当 bug 改：

- `resolveDatabaseId` 只在 01 里 —— 线上件把它换成了 `const DATABASE_ID='...'`
- `finExport` 查了但可能不存在 —— 代码用 `if(el)` 兜住，属可选挂件

## ⚠️ 更新线上版：必须打补丁，不能整份替换

本地母版（`Sea-2.8.html`）里**没有** `inject.js` 脚本标签，也没有那 500 多个 `data-page-node-id`。整份覆盖上去 = 平台注入入口没了 = `window.__SMART_PAGE__` 拿不到 = 云端同步静默失效。

正确做法（2026-10-29 实操验证过）：

```bash
# 1. 开事务，拿到基线版本与 CDN 目录
python3 page/create_page_transaction.py --node-id <页面节点 ID>

# 2. 下载线上那份，作为「带锚点的基线」
curl -fsSL "<url>Sea人生工作台.html" -o live.html

# 3. 把本地相对上一个线上版本的改动做成补丁
diff -u <上一个线上版本的本地副本> Sea-2.8.html > sea.patch

# 4. 打到线上基线里（带属性，会有些 hunk 冲突，逐条人工补）
cp live.html new.html && patch -p0 --fuzz=0 new.html < sea.patch

# 5. 上传 + 提交
python3 page/upload_page_artifact.py --transaction-id <tx> --path "Sea人生工作台.html" --file new.html
python3 page/commit_page_transaction.py --transaction-id <tx> --message "..." 
```

打完补丁必须核对四件事，缺一条都别提交：

1. `grep 缺失元素` —— 所有 `getElementById('x').onclick` 里的 id 都还在（曾因正则贪婪误删过三个 set-row）
2. `grep "DATABASE_ID='"` —— 线上版**应该**还有这个硬编码（值是你的库 ID）
3. `node --check` 两个 script 块都过
4. `SEA_FILE=<补丁后文件> node tests/*.mjs` 全绿（`inject.js` 404 是 file:// 下的正常现象，不算错）

### ⚠️ 不要用 `--fuzz`（v2.10 踩过）

`patch --fuzz=3` 会「忽略 3 行上下文」强行落位，**结果是静默错位**：v2.10 那次它把「存档文件」整行塞进了「流水导出」那一行内部，还留下一个空的 `set-row`；结构错了但语法没错、测试也不报。

正确做法：**`--fuzz=0` 严格打**，让带 `pnid` 属性的块全部失败，再手工补。v2.10 一共失败 5 处，全是同一个原因 —— 平台把属性顺序改成了 `content=... name=...`、并在行内插了 `<!--pnid:...-->`：

| 失败块 | 手工补法 |
|---|---|
| `meta version` | 匹配 `content="x" name="version"`（不是母版那种顺序） |
| `setVerNum` | 值前面可能夹着 `<!--pnid:...-->`，用正则 `(id="setVerNum">)(<!--pnid:[^>]*-->)?` |
| body 顶部新增节点 | 按「`id="saveState"` 那一行之后」插入整段 |
| 设置面板新增行 | 按「`id="btnImport"` 之后的第一个行级 `</div>`」之后插入 |
| JS 新增模块 | 按 `// 初始化：优先加载` 注释前整段插入，再单独改 `init` 头部 |

补完后必查三个数字：`set-row` 数量（原 5 → 应 6）、空 `set-row` 应为 0、`data-page-node-id` 行数不得减少。

## 公开版怎么来的

不是「从母版裁剪出来」，而是**从 git 白名单原样复制**：`.gitignore` 已经把私有资产排除了，`git ls-files` 列出来的就是可公开的全部。所以 02 与 01 的对应文件**逐字节相同**，不需要任何删改步骤。

```bash
node scripts/export-public.mjs          # 重新生成 Sea/02-GitHub发布版/
node scripts/export-public.mjs --dry    # 只看会动哪些文件
```

公开版唯一要保证的性质：`DATABASE_ID` 解析链在无宿主环境下返回空（`resolveDatabaseId` 找不到宿主又没有 `?db=` → `cloudReady()` 直接 false → 纯本地）。母版本身已经是这个状态。

## 加新功能时，补丁里最容易漏的四块

平台注入的东西是 `inject.js` + 每个元素上的 `data-page-node-id` / `<!--pnid:...-->` 锚点。v2.10 加「存档文件」时踩到的清单，以后加功能照这个顺序核：

1. **新增的 DOM 要整块插**（`#fileState` / `#filePerm` 在 `<body>` 顶部），平台不会给它们补锚点 —— **没有锚点不影响运行**，只是这个元素在编辑器里选不中。别为了补锚点去手写 `data-page-node-id`。
2. **新增的 CSS 段整段插**（`/* 存档文件镜像 */` 开头），锚点注入不会碰 `<style>`。
3. **`getElementById(...)` 的可选元素要写空判**：`const el=document.getElementById('x'); if(el) ...`。补丁漏一段时，硬取属性会直接抛错、整个 `bindDomainButtons` 后面的绑定全不执行 —— 这是最难查的那种「点了没反应」。
4. **`SEA_FILE=<补丁后文件> node tests/verify-file.mjs`** 必须全绿：它专门验「元素缺失时优雅跳过」这一路径。

## 线上版回滚

平台没有版本回滚 API。唯一退路是本地备份：`.private/Sea-备份/Sea-线上2.8.5-回滚备份.html`（v2.9 升级前的线上原样副本）。再上传一次即可回到 v2.8.5。
